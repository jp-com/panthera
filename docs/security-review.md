# Security hardening
The build externalizes inline scripts and applies a Content Security Policy without unsafe-inline JavaScript, HTTPS transport, frame blocking, no-referrer and limited permissions. Inline CSS is still permitted for approved static layouts; Meta script/network origins are restricted and marketing is opt-in. Request JSON and raw webhook payloads are bounded before buffering. Checkout compares the server quote with the accepted total and refuses stale prices; the client must refresh its quote. Shared per-minute database request budgets cap checkout, quote and tracking requests across serverless instances, with failure closed when the table is unavailable. These are global limits, not bot detection; they can temporarily block legitimate users during abuse. Configure Vercel per-IP WAF limits, bot mitigation and monitoring separately; do not challenge Stripe webhook traffic. Suggested starting limits: checkout 10/min/IP, quote 60/min/IP, order status 30/min/IP, admin requests 30/min/IP; validate in log mode first. Current connector does not have firewall read access; no firewall rules were changed.
Apply 002_admin_audit and 003_security_limits migrations in isolated preview and independently in production before activation. Schedule deletion of request-limit rows older than 24 hours (no schedule configured yet). Separate migration/runtime roles, independent environment credentials, backups, alerting, managed admin identity/MFA, WAF rules, dispute workflow and full Stripe/payment integration tests remain required. No live payment, marketing or administrative writes have been enabled. The manual SECURITY_REVIEW_APPROVED flag is a launch gate, not a certification. Configure only after the checklist is verified.
