# Order status
A signed, 180-day bearer capability grants read-only access to a single order. It is not the order reference, customer email, or an enumerable order number. The API accepts the capability in a POST body and omits names, email and street address. The order-status response contains the reference, payment and fulfillment state, totals, items and shipment tracking information. Configure ORDER_TRACKING_KEY as a separate random 32-byte hex secret per environment (never commit it); rotation invalidates prior capabilities. Checkout issues a capability after receiving a valid open Stripe session. The browser retains it in sessionStorage and links to /track.html. It is not sent to Stripe or Meta. The tracking page supports private emailed links in the URL fragment; fragments are immediately removed from the browser URL and never transmitted to the server. The email worker, not yet implemented, should issue a fresh capability for confirmation/dispatch and include /track.html#access=TOKEN only in messages sent to the verified order email. Do not add analytics to tracking or success pages. A rate limit, access-recovery process, independent preview/production database roles and integration tests are required before launch. No test orders, emails or payments were created.
